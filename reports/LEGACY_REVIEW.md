# 重新检查 Crum3 / Crum4 后的取舍

本次直接读取了 crum3 的解析、语料匹配、训练集合并、特征、训练脚本，以及 deploy/crum4 的检索、评测、负例和界面代码，并重新运行 Crum4 自带测试（12/12 通过）。原代码及数据保持不变。

## Crum3 保留的关键想法

- parse_v15.py / match_crum_to_corpus_v15.py：以 Crum 的专业词头、释义、引用顺序构造监督。当前以全量标记审计替代原部分引用输出，保留原始顺序和不确定绑定。
- merge_training_v15.py：priority 1/2/3 对应 3/2/1；Crum 从 3 每次减 0.1，最低 1。新消融直接对照这套 Crum 赋分与连续相对位置。旧脚本将缺失 priority 默认赋 1，并会取首个语料匹配；新流程保留顺序未知，保留见证和歧义。
- add_features_v15.py / train_v15_sm.py：GDEX、详细词性/依存计数和 sense match。新实验从原生 TT 标注重新计算详细 UD 特征，与紧凑 UD 组作消融，没有把旧模型直接用于列含义不同的新特征。
- 原 lgbm_v15_* 模型曾见过旧训练行。把它们直接用于同一批行只会得到训练内成绩，因此本次对照重新训练相同思路的模型，使用固定词形家族验证折，不冒充原模型的独立测试。

## Crum4 需要特别保留的工作

retrieval.py 将检索范围扩大到全语料，以词形/POS 找候选，再粗筛最多 100 条，以真实 BGE、ROUGE-L、词频排序。这是词义相关性的重要基线，不是 Crum3 树排序器的另一份部署。

原公式是 0.55 cosine + 0.30 ROUGE-L + 0.15 词频分。词频分是候选内容词 lemma 的平均频率经 log1p 后除以该候选池最高值。新消融调用原 Crum4 的分词/ROUGE 定义，读取原词频和真实 BGE 缓存，并添加公式一致性测试。它没有用单句质量冒充第三项。

evaluate_crum4.py 的旧报告在种子 42 抽取的 100 个 TLA 上，旧离散 NDCG@6=0.7885、线性 NDCG@6=0.9047。它是固定公式对旧候选的评价，不是学到参数后单独留出的训练测试。新数据、gain 和候选均不同，不能直接与本次表格比高低。

本次 Crum4 对照在有真实缓存向量的相同新候选子集上运行，未把缺失向量替换为零，也没有为凑覆盖调用大模型。原检索的 top-100 粗筛未在这个排序消融中应用，因为它会改变考题；因此这里测试的是原评分公式，不是整个原检索系统的端到端召回。

training_negatives.py 保留了同形词 hard negatives 和最多 10% 随机负例的思路。但“同形”不能保证“互斥义项”。本次测试朴素同形词方案与仅 barley/father 的保守方案，派生负例只加在训练折，不能覆盖原人工正例。

data/README.md 已详细记录缺失的旧数据库入口，以及 Sahidic/Bohairic 旧导出的不同版本；这些核对很有价值。新项目没有把旧导出改名当作重新生成结果，而是用 XML 词典和 TT 原语料重新建候选。
