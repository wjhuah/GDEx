# 从零理解这个例句推荐项目

这份指南假定你没有机器学习背景。你只需要记住：我们先找全例句，再判断它是否适合这个词义、是否值得收录，最后让三条例句展示不同用法。

## 第一步：打开网页，先实际试一次

打开 http://localhost:8012 。输入 C998，选择 Sahidic，再点击“推荐例句”。C998 是 barley；C992 是 father。它们的科普特语形式相同，但词义不同，所以不能只看字符串命中。

页面先显示词条和方言，然后显示十条左右的候选。每条都有原文、译文和引用。点开“这条为什么入选”可以看质量、Crum 风格和句法结构。再看“三句集合对照”，比较直接取前三和照顾不同句法用法的选择。

切到 Bohairic 后必须重新查询。没有该方言候选时显示空结果；不会拿另一方言的例句填上。Bohairic 证据很少，页面会明确显示“暂定”。

## 第二步：我们从哪里知道什么算好

一个来源是 citations_manual_merged.tab。有人明确选中的例句，说明“值得收录”。priority=1/2/3 又额外告诉我们先后。没有 priority 的例句也可能很好，只是我们不知道它应该排第几。明确 forbidden 的句子是负例；没有被标注的句子是未知，不能随便当坏例子。

另一个来源是 Crum 词典。它的原始顺序体现专业编纂偏好。我们学习同一词条段落内的先后；排在后面不意味着句子糟糕。两种来源分别形成训练问题，不假装 Crum 顺序和 TAB 的好坏标签完全相同。

数字化 Crum 的 41,808 个显式 Bible 标记已全部保留，并能逐条切回原文。这个数只证明显式标记没有丢，不证明每条都已找到正确 TLA、方言和语料句子。未确定的项有单独复核队列，不混作正确训练句。

这里的候选单位来自 TT 的 verse/translation 片段，并不保证每条都是独立完整句，也不保证 Coptic 片段与英文译文长度完全对应。它们仍需要人工复核；推荐算法不能自动修好原语料的所有对齐问题。

## 第三步：3、2、1、0、−1 到底是什么意思

3/2/1 可以表达人工第一、第二、第三优先。它们是等级，不是测量出来的三倍、两倍好。−1 可以在证据表里表示明确禁用；排序程序内部把负例的相关度记为 0。未知例子既不是 0，也不是 −1。

现在 TAB 的优先级转换成 1、2/3、1/3；收录和禁用另外形成 1/0 的问题。一个没有顺序的正例不会被偷偷赋成第三名。

对于 Crum，同段落实际可用引用从先到后得到 1 到 0.2 的连续相关度。例如四条依次为 1、0.733、0.467、0.2。这个间距是公开的建模假设，原始顺序始终保留。旧方案是从 3 每次减 0.1，到 1 后所有后续引用持平。消融表比较了两种训练方案，评价标准保持一致。

## 第四步：机器怎么给句子打分

你可以把每个句子想成一张体检表：句长多少，生僻词多少，目标词出现在哪里，句子有几个从句，目标词有没有修饰语。树模型不断用这些数值分组，学习哪些组合更符合已知偏好。

GDEX 特征主要看可读性和自足性：句长、词频、重复、标点等。这里借鉴 GDEX 思路并实现适合本地数据的特征，并没有宣称复制了完整官方 GDEX 系统。

UD 特征看句法：主语、宾语、从句、依存树深度和目标词在主句还是从句。细 UD 消融还加入各种词性/依存关系计数、树宽度等，思路来自 Crum3，重新从现在的语料标注计算。

信息量特征看目标周围：修饰语、属性描述、论元和上下文实词。苹果例子中“又大又红”提供了更多描述。但信息多也可能变得难懂，所以不能只奖励句子长。

义项词面特征看词典释义和译文的实词重合。默认研究树共 45 个特征。另做了真实 BGE 缓存语义特征的实验，默认推荐不加载它，也不调用大模型。

树模型可以处理许多特征，但不保证新增特征一定有用。无关或噪声特征会让它学错规律。消融就是每次拿掉或加入一组，再看同一批测试题上的变化。

## 第五步：为什么不能用训练时的成绩当结论

如果老师把答案和题目一起教给学生，再原题考试，成绩再高也说明不了多少。我们把词形家族分成五份，轮流留一份考试。barley 和 father 的同形词家族放在同一份，避免同形词信息跨折泄漏。

测试出现的完全相同 Coptic 原文也从训练来源和派生负例中清除。近似重复、译文改写仍可能存在，尚未证明所有隐性重复都消失。

所有方法在相同候选上考试。有 BGE 缓存的子集是另一个考场，只能在那个子集内部比较。不能把两张不同试卷上的分数直接相减。

我们还用这些考试结果选择了当前模型，所以仍需一份没有参与选择的独立测试。现在的数字属于探索性研究结果。

## 第六步：读懂实验页面的指标

NDCG@6：看前六条是否把更合适的句子放在前面，再除以这组已知标签能达到的最好排序。1 表示这道题的排序最佳；0.785 不等于 78.5% 的例句正确。候选标签差距小、题目少时，随机排序也可能很高。

成对准确率：每拿两条有明确高低的例句，模型把更好的排在前面的比例。0.5 通常相当于随机猜，并列也计半分。页面详情同时提供它，防止只看高 NDCG。

已知候选 P@3：前三条中，已知人工正例占多少。它只对已有正负标签的候选池成立，不是未知全语料前三条的实际准确率。

组数：我们实际考了多少道排序题。人工有序组只有 11 个，不能像 962 个 Crum 组那样解读。Bohairic 没有正负混合的人工收录组，所以相应指标显示“无法评估”，不是 0 分。

Δ：左边方法减去右边方法。+0.02 表示这个指标增加了 0.02。95% 区间用词形家族反复抽样，说明估计有多不稳定；区间跨 0 时，不能确信方向。这里做了很多比较，区间也没有作多重比较修正。

AUC：另一个单句收录分类任务的指标，衡量随机取一个正例和一个负例时能否把正例打得更高。0.5 接近随机。先前报告的 AUC 约 0.63 与当前排序 NDCG 约 0.785 是不同任务，不能说从 0.63 提升到 0.785。

## 第七步：读懂每条例句下面的数

推荐分：默认研究树的原始排序分经过单调变换成为 0 到 1，方便显示。它只是同次查询中的排序依据，不是正确率；不同词条之间也不宜直接比较。可切换的“质量优先组合”使用 0.60 单句收录分 + 0.25 联合树归一化顺序分 + 0.15 信息量。它提升了全语料候选的单句模型分，但留出排序成绩较低，因此没有替代默认研究树。两者成绩分开报告，不能只挑好看的数字。

单句收录分：独立模型根据人工收录/禁用学习的数值。训练有类别平衡，未经概率校准，因此 0.8 不等于有 80% 的概率是好句。候选至少达到池内最高收录分的一半，才允许进入多样性选择。

Crum 风格百分位：在本次候选中比多少候选更符合风格模型。90% 表示相对位置靠前，不表示 Crum 本人认可概率为 90%。它来自另一个风格模型，作为可解释参考；研究树已经联合学习了 Crum 顺序。

信息量分：公开规则对修饰、内容词和论元作的归一化摘要。它不是人工真值。

句法标签：role:nsubj 表示目标作主语；role:obj 表示宾语；modifier 表示目标有修饰；clause 表示主句/从句位置；frame 表示周围谓词和论元结构。它们依赖当前语料标注，标注错也会影响选择。

## 第八步：十条怎样变成三条

先在整个词条、本方言候选池计算便宜特征。过滤禁用、不可用译文、重复，以及 C992/C998 缺乏明确词面义项证据的候选。后一个过滤偏保守，可能漏掉释义间接的好例句。

通过单句质量门槛后，取高分池，并要求组合分至少达到最高分的 65%；再兼顾不同句法结构选择十条。没有足够好例句时可以少于十条。

三句实验比较直接前三、句法 K-means、十条中穷举三条。十条中选三条只有 120 种组合，本地完全算得动。目标是单句质量、句法覆盖和少重复之间的折中。

覆盖率表示这三句覆盖了十条候选中多少种自动句法特征，不表示覆盖这个词全部真实用法。对少见结构的奖励也可能牺牲单句质量，所以两个数必须一起看。目前没有大模型十选三，网页显示的是本地研究对照。

## 第九步：barley 能不能当 father 的负例

词形相同不代表词义相同，Amir 的想法值得测。四个人工锚点都更支持自身义项。新留一测试又把每个锚点从训练里清掉，有无交叉负例都区分对了四个，所以暂时看不到额外收益。

“负例”指对某个目标词义不合适，不要求向量相似度小于零。一个 barley 句子与 father 的相似度仍为正数，也可能是 father 的候选负例；这是标签和相似度的区别。

主消融中，便宜模型加入这个负例后略降；缓存 BGE 子集略升；两者区间都跨 0。默认因此不采用，保留实验。把所有同形词一律当相互负例下降更多，因为近义义项或同句含多个义项会制造假负例。

主实验把同形词放在同一折，所以测试 C992/C998 的那一折不能用这对词的训练负例。主实验考察的是这种增广能否推广到其他未见词形；四锚点留一诊断则允许其余同词家族参与训练，考察词内区分。两个实验回答的问题不同，都不足以代替新的独立义项标注。

这个结论不是“Amir 错了”，而是现有标注不能证明它能改善推荐。下一次需要独立标注：目标 token 到底是什么义项、这个句子对另一义项是否不合适。

## 第十步：维护、复现和融合词典

所有新代码在 coptic_examples_rebuild，旧 crum3、crum4 和 dictionary 文件未修改。网页沿用词典的蓝底、黑导航、半透明浅色内容区、Coptic 字体和深红引用色，方便日后把例句组件迁入。

接口 POST /api/search 接受 query、dialect、ranker。ranker=research 为当前研究树；cheap 为原单句质量与风格双任务基线。返回原文、译文、引用、分项和方言，不要求前端知道训练细节。新增方言在 dialects.toml 配置；再构建它的索引、标签和独立模型。不能仅增加菜单文字。

重跑核心消融：python scripts/run_ablations.py --rebuild 。训练研究模型和留一诊断：python scripts/finish_research.py 。重建可读报告：python scripts/publish_research.py 。运行测试：python -m unittest discover -s tests -v 。本机可用 ../crum3/.venv/bin/python 替代 python。

现在最值得做的下一步：复核 Crum 绑定；补 Bohairic 标注；把不同方法的名字藏起来，让专家盲评每个词的十条和最终三条。大模型选三条留到下一阶段。
