# 运行和迁移注意事项

入口支持安装后的 `coptic-examples` 或源码目录里的 `python run.py`。外部原始资料根目录由 `COPTIC_SOURCE_ROOT` 或 CLI 的 `--source-root` 指定；新缓存、导出、报告和模型始终写进本目录。

`build` 的指纹包含 schema 版本、TT 相对路径、大小和纳秒修改时间；不等于每个 TT 的内容哈希。原始重要输入的 SHA-256 在 source manifest 中。修改输入或算法后按 README 重跑，不把旧模型和新特征混用。

向量缓存以模型名称、角色、规范化文本 SHA-256 分区。BGE 初次必须预先下载，运行时禁止悄悄联网换权重；缺失模型、坏维度或零向量会明确失败。原项目缓存只复用真实 1,024 维向量，不复用旧标签、排序分数或不完整 gloss 的 cosine。

本机 macOS/Python 3.14 环境验证中发现过“先加载 Torch/MPS，后懒导入 LightGBM”的进程崩溃。检索入口现提前导入 LightGBM，再加载 BGE；已经实际执行“新文本 BGE 编码后立即 learned 推理”验证通过。没有使用忽略重复 OpenMP 运行库检查的环境变量掩盖问题。

所有 SQLite 连接在上下文退出时显式关闭。对外部旧数据库只读核对，没有运行会写旧 examples 表的生成器。新 corpus 索引先建临时文件再原子替换；不要同时运行两个 build/dataset，也不要在正在提供检索时重建索引。

全局导出包含原始片段，即便缺译文、为标题或被禁用，也保留其追溯信息；推荐结果另按明确规则过滤。大写的文献标题（如 FOURTH MARTYRDOM OF…）在展示推荐时排除，过滤计数单列，不能称为模型自己学会的能力。

`scripts/rebuild_crum.py` 有意复用旧项目两份 OCR/书卷名解析实现，通过模块导入后覆盖输入输出配置运行；所有实现哈希有记录。它不是一套独立重新发明的 OCR 工具，迁移机器时需要保留这两份上游实现，或将其作为有来源记录的版本化依赖迁入。数据清洗、标签处理、特征、训练、检索和网页均在新包中实现。
